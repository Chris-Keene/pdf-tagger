Installing PDF Tagger

Takes about a minute. There is one step where macOS will refuse to open the app — that is expected, and step 3 gets you past it for good.

VersionPDF Tagger 1.21.0
NeedsmacOS 12+, Apple silicon
DownloadPDF-Tagger-1.21.0.zip · 89MB
NetworkNone. Works offline

01Install it

  1. Unzip the fileDouble-click PDF-Tagger-1.21.0.zip. You will get an app called PDF Tagger.
  2. Drag it into ApplicationsNot strictly required, but it is where you will look for it next week, and apps left in Downloads can behave oddly.
  3. Open it, and expect to be stopped onceThe first double-click will be blocked by macOS. Nothing is wrong with the app. The panel overleaf clears it for good.

What you need

A Mac with Apple silicon — an M1 or later, so anything bought since roughly 2021. Nothing else to install, no sign-in, and it works offline. On an older Intel Mac this build will not open at all: open the Apple menu and choose About This Mac, and if it says Intel, ask for a build that suits.

02“macOS cannot check it for malicious software”

You will see this the first time you open the app, and only the first time.

  1. Double-click PDF TaggerA message appears saying macOS cannot verify it. Click Done (or OK, or Cancel — whichever it offers).
  2. Open System SettingsThe grey cog in your Dock, or press ⌘ + Space and type “System Settings”.
  3. Click Privacy & SecurityIn the left-hand list.
  4. Scroll down to SecurityThere will be a line saying “PDF Tagger was blocked to protect your Mac.”
  5. Click Open AnywayThen confirm with your password, Touch ID or Apple Watch.
  6. DoneThe app opens, and from now on it opens like anything else.

Why does this happen?

Apple charges an annual fee to register apps so they open without a warning. This is an internal tool that has not been through that, so macOS treats it as an unknown developer. It is not a sign that anything is wrong with the file.

Faster route, if you are comfortable with Terminal

This skips the whole panel above. Open Terminal, paste the line, press Return, then open the app normally.

xattr -d -r com.apple.quarantine "/Applications/PDF Tagger.app"

If you put the app somewhere other than Applications, change the path to match.

03Using it

The app opens filling the screen, and works through five steps along the top of the window. Each one explains itself as you go.

  • Open a PDF. Drop one onto the window, or click Choose a PDF. You can also right-click any PDF in Finder, choose Open With, then PDF Tagger.
  • Leave “Help tips on” while you are learning. When the explanations start getting in the way, switch them off with the button in the top right.
  • Your original file is never changed. The last step saves a new, tagged copy alongside it.
  • On a longer document it goes page by page. The strip of thumbnails shows what is still outstanding on each one, and the button at the bottom right moves to the next page rather than skipping to the end.

Optional: let Claude help with the two hard parts

Two jobs in this app cannot be done by a script: writing a description for each image, and judging whether a page reads in a sensible order. If you have Claude Code installed and signed in, the app can offer both. It is off until you switch it on, per document.

  • Drafting descriptions sends a crop of each image, and the text near it, to Claude. Not the whole page, and not the rest of the document.
  • Checking reading order sends only the words and where they sit. No image ever leaves the machine for this one.
  • Nothing is accepted for you. A drafted description arrives marked as a draft and still counts as outstanding until you have read it against the picture. That is deliberate: a description that reads well and describes the wrong thing passes every automated check and helps nobody.
  • Think before using it on customer material. Switching it on means content leaves this Mac. For a deck you would not paste into a chat window, leave it off and write the descriptions yourself.

Fixing what it gets wrong

Most of the work is confirming what the app proposes. Where it has grouped something badly, the tools are on the item itself:

  • Drag the handle — the grip of small dots at the left of each row — to move an item in the reading order, or use the up and down arrow buttons. Both do the same thing.
  • Split breaks one item into separate pieces — for when two things sitting side by side, like table cells, have been counted as one.
  • Join up does the reverse, for a sentence that has been chopped in half.
  • Click anything on the page preview to jump straight to it in the list, and zoom in if the boxes are too close together to tell apart.

04If something goes wrong

Common messages and what they mean
It will not open even after “Open Anyway” Move it into your Applications folder and try once more.
It says the PDF is password protected It is. Remove the password on the original, then try again.
It says some of the text cannot be tagged Some PDFs store text in a way this app cannot reach. It tells you rather than pretending it worked. The fix is to re-export the document from wherever it was made.
It says a font is not stored in the PDF Same kind of thing: no amount of tagging can add a missing font. It has to be re-exported with the fonts embedded.
It warns the tagged copy will not be password protected Correct. Tagging has to rewrite the file and it comes out unprotected. The content is identical; re-apply the password to the copy if it matters.
Anything else There is a log at ~/Library/Logs/PDF Tagger.log. Send that on with a note about what you were doing.

05Distribution notes

For whoever is handing this out

  • Send PDF-Tagger-1.21.0.zip (89MB). Zipped with ditto, so the code signature survives the transfer. Slack, Drive and email are all fine at that size.
  • Everyone will hit the Gatekeeper warning. The app is ad-hoc signed rather than signed with a Developer ID. Verified: a received copy picks up the quarantine flag and spctl rejects it.
  • On macOS 15 the old shortcut, Control-click then Open, no longer works for this, which is why the instructions above use System Settings. Sending people the old right-click trick will fail at the first step.
  • To remove the friction entirely the app needs a Developer ID and notarisation: an Apple Developer account at roughly £79 a year, then signing and stapling the build. After that it opens with no warning and these instructions shrink to “unzip, drag, open”. Worth it past a handful of people; overkill for a pilot.
  • Apple silicon only. The build is arm64, so an Intel Mac cannot run it. A universal build would need universal2 wheels for pikepdf and PyMuPDF — doable, not free.
  • veraPDF is bundled, so recipients get the real conformance verdict without installing Java or Homebrew — the veraPDF CLI plus a jlink-trimmed OpenJDK runtime, verified to give a verdict identical to a system install with no Java on the PATH. It accounts for 63MB of the download; --no-verapdf builds a 45MB version that tags identically but shows no pass or fail.
  • Licensing for the redistributed parts: veraPDF is dual GPL-3.0-or-later / MPL-2.0, included under MPL-2.0 (file-level copyleft, nothing imposed on our source). The runtime is OpenJDK under GPLv2 with the Classpath Exception, which is what permits shipping a trimmed runtime inside an app. Licence texts ship in Contents/Resources/verapdf/.
  • Nothing is installed, and nothing leaves the machine unless somebody switches it on. The app runs a local server on 127.0.0.1 for its own window to talk to, on a random port. The one exception is the optional Claude help described below, which is off until the user turns it on, per document.
